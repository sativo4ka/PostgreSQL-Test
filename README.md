# Тестирование SQL-запросов в PostgreSQL

## 1. Цель работы

Создание реляционной базы данных PostgreSQL, состоящей из связанных таблиц, заполнение базы тестовыми данными и проверка SQL-запросов.

## 2. Используемые технологии

- PostgreSQL 18
- pgAdmin 4

## 3. Структура базы данных

В базе данных `test_database` созданы пять таблиц:

| Таблица | Назначение |
|---|---|
| `customers` | Хранение информации о покупателях |
| `categories` | Хранение категорий товаров |
| `products` | Хранение информации о товарах и их ценах |
| `orders` | Хранение информации о заказах |
| `order_items` | Хранение состава заказов |

Для организации связей между таблицами использованы первичные и внешние ключи.

## 4. Выполненные SQL-запросы

### Запрос 1. Покупатели с заказами в текущем месяце

Запрос находит покупателей, совершивших заказы в текущем месяце, рассчитывает общую стоимость их покупок и сортирует результат по убыванию суммы.

### Запрос 2. Товары дороже средней цены своей категории

Запрос сравнивает цену каждого товара со средней ценой товаров в его категории, в результат попадают только товары, стоимость которых выше среднего значения.

### Запрос 3. Заказы с товарами категории «Электроника»

Запрос находит заказы, содержащие товары из категории «Электроника», и сортирует их по дате оформления.

### Запрос 4. Покупатели без заказов в прошлом году

Запрос находит покупателей, у которых отсутствуют заказы за предыдущий календарный год.

### Запрос 5. Товары, которые никогда не заказывали

Запрос находит товары, отсутствующие в таблице состава заказов.

## 5. Проверка базы данных

В ходе тестирования проверяются:

- наличие записей во всех пяти таблицах;
- корректность первичных и внешних ключей;
- ограничения уникальности и допустимых значений;
- наличие индексов;
- выполнение SQL-запросов;
- производительность запросов с помощью `EXPLAIN ANALYZE`.

## 7. Ошибки и предупреждения

Для проверки запросов, связанных с предыдущим календарным годом, необходимо учитывать актуальность тестовых дат.
Из-за небольшого объема тестовых данных оценка производительности индексов носит предварительный характер.

Критических ошибок в логике запросов на этапе подготовки не выявлено. Окончательный результат проверки определяется после выполнения всех запросов.

## 8. Рекомендации

- Использовать индексы для ускорения выполнения запросов.
- Проверять корректность связей между таблицами.
- Использовать ограничения для предотвращения некорректного ввода данных.
- Анализировать планы выполнения запросов с помощью `EXPLAIN ANALYZE`.
